Direct aanpakken

Deze vier zijn kritiek: ze raken echt geld of persoonsgegevens van kinderen, en ik heb ze stuk voor stuk in de code bevestigd. Begin hier voordat je nieuwe features bouwt.

Kritiek

Refund draait zichzelf terug — klant houdt geld én credits

✓ geverifieerd
src/lib/payments/orders.ts:163-200

Na een admin-refund staat de order op refunded en zijn de credits teruggeboekt. Mollie stuurt bij een refund echter opnieuw een webhook, en de betaling zelf blijft paid. De code doet dan wasPaid = order.status === "paid" → onwaar (status is "refunded") → becomesPaid = true → credits worden opnieuw bijgeschreven en de order springt terug naar "paid". Elke webhook-retry triggert dit.

Fix "refunded" als eindstatus behandelen (vroeg return) en de paid-transitie claimen met een status-guard (zie hieronder).

Kritiek

Betaling niet atomair verwerkt — dubbele credits & dubbel incasso-schema

✓ geverifieerd
src/lib/payments/orders.ts · applyCreditsPaid / applySubscriptionFirstPaid

De webhook én de terugkeerpagina van Mollie roepen allebei applyMolliePaymentStatus aan op precies hetzelfde moment. Beide lezen status "pending", beide zien becomesPaid, beide draaien de transactie — die géén where status = 'pending'-conditie heeft. Resultaat bij credits: dubbele credits. Bij abonnementen erger: beide roepen customerSubscriptions.create bij Mollie aan → twee actieve incasso's op één mandaat, waarvan er één onzichtbaar blijft doorlopen.

Fix transitie claimen met order.updateMany({ where: { id, status: { notIn: ["paid","refunded"] } }, data: { status: "paid" } }) en alleen bij count === 1 credits/abonnement toekennen. Claim óók vóór de Mollie-subscription-create.

Kritiek

Profiel of verhaal verwijderen laat kindfoto's & illustraties permanent staan

✓ geverifieerd
src/app/api/children/[childId]/route.ts:83 · src/app/api/stories/[storyId]/route.ts:68

Beide DELETE-routes doen uitsluitend prisma.…​.delete(). Geen enkele storage-cleanup. Alle Scaleway-objecten blijven staan — illustraties (mogelijk met het gezicht van het kind), voorleesaudio, de goedgekeurde profielfoto. Omdat de database-rij (de enige plek met de URL's) weg is, kan latere accountverwijdering ze nóóit meer terugvinden: permanent én publiek leesbaar. Dit is in strijd met je eigen privacyverklaring en met art. 17 AVG (wissingsrecht).

Fix vóór de DB-delete de storage-keys verzamelen en deleteObjects draaien — het patroon staat al in de regenerate-route. Plus een eenmalige opruimactie voor de reeds verweesde objecten.

Kritiek

LoRA-trainingsset (5-15 kinderfoto's) wordt nooit verwijderd

✓ geverifieerd
src/lib/ai/lora-training.ts:175-190

deleteTrainingAssets wist alleen de losse foto-URL's; de ZIP op lora-training/<childId>/training-set.zip blijft staan — een commentaar in de code erkent dit letterlijk. De zip verdwijnt niet bij training-succes, niet bij consent-intrekking, niet bij accountverwijdering, en staat public-read op een voorspelbaar pad. Dit is data die je eigen privacyverklaring als biometrisch (art. 9 AVG) bestempelt.

Fix in deleteTrainingAssets altijd ook de deterministische zip-key meewissen; eenmalige opruimactie voor bestaande zips.

De drie geldstroom-fixes horen bij elkaar

Refund-hercreditering, dubbele credits en dubbele abonnementen los je met één ingreep op: een conditionele status-claim via updateMany die de betaal-transitie precies één keer laat plaatsvinden, plus een guard op "refunded". Dat is de belangrijkste code-wijziging van deze hele analyse.

01

Veiligheid

De autorisatie is opvallend degelijk: elke route scoopt eigendom via childProfile: { userId } en geeft 404 bij mismatch. Geen IDOR's, geen gecommitte secrets, webhooks vertrouwen client-input niet. De aandachtspunten zitten in verouderde dependencies, registratie-misbruik en hardening.

Hoog

Next.js 16.2.1 heeft 14 bekende hoog-ernstige lekken

✓ geverifieerd
package.json · "next": "16.2.1" → advisories t/m 16.2.6

De pnpm audit meldt o.a. meerdere proxy/middleware-bypasses (relevant want je auth leunt op proxy.ts), SSRF via WebSocket-upgrades, DoS in de Image Optimization API en XSS via CSP-nonces. Allemaal gepatcht in recente 16.2.x.

Fix pnpm up next@^16.2.6 (of hoger) + opnieuw builden/deployen. Grootste beveiligingswinst voor de minste moeite. Overige advisories zitten in dev-only transitieve deps (prisma→hono, sentry-webpack) en zijn niet in de runtime bereikbaar.

Hoog

Registratie heeft geen rate-limiting of bot-bescherming

✓ geverifieerd
src/app/api/auth/register/route.ts:19-76

Elk nieuw account krijgt direct 5 story-credits (echte Claude/fal.ai-kosten) en stuurt een admin-notificatiemail. Zonder limiet kan een script massaal accounts aanmaken: gratis credits farmen, je admin-inbox floodden, en welkomstmails als spam naar willekeurige adressen sturen. De nieuwsbrief-signup is wél beveiligd met rate-limit + honeypot; registratie niet.

Fix hergebruik de bestaande per-IP rate-limiter + honeypot, net als bij nieuwsbrief/contact.

Middel

E-maillinks worden uit de request-host gebouwd (reset-poisoning)

src/lib/url.ts:15-28 · getAppBaseUrl

Reset-, magic-link- en unsubscribe-URL's gebruiken x-forwarded-host ?? host in plaats van een vaste env-URL. In theorie kan een gespoofte host een geldig reset-token naar een aanvaller-domein sturen (account-overname). Op Vercel wordt die header normaal door de edge overschreven en geeft een onbekende host 404 vóór de functie draait — praktische exploiteerbaarheid is dus laag, maar de code is fragiel (breekt bij self-host/preview-aliassen).

Fix e-maillinks pinnen op NEXT_PUBLIC_APP_URL, niet op de request-header.

Middel

CSP staat unsafe-inline én unsafe-eval toe

next.config.ts:100

De rest van de header-hardening is uitstekend (HSTS+preload, frame-ancestors none, object-src none, strak Permissions-Policy), maar script-src biedt zo nauwelijks XSS-vangnet. Er is nu geen gebruikersdata in een gevaarlijke sink gevonden, dus rest-risico is laag; de mitigatie ontbreekt alleen.

Fix nonce-based CSP (staat al als geparkeerde follow-up in een comment); minimaal unsafe-eval eruit.

02

Privacy & AVG

Dit is de zwaarste categorie, want de app verwerkt persoonsgegevens van kinderen. De accountverwijdering en fotomoderatie zijn doordacht gebouwd, maar de losse verwijderpaden en de publieke opslag laten kinddata achter die je hebt beloofd te wissen. De twee kritieke punten staan bij "Direct aanpakken"; hieronder de rest.

Hoog

Alle kind-assets staan public-read met een jaar immutable cache

✓ geverifieerd
src/lib/storage/scaleway.ts:83-84

Elke upload krijgt ACL: "public-read". Wie een URL heeft, haalt zonder sessie of expiry referentiefoto's, illustraties en audio op. De UUID's maken raden onhaalbaar (goed), maar URL's lekken via cache, browsergeschiedenis en gedeelde apparaten — en een deellink intrekken maakt de onderliggende beeld-/audio-URL's niet ontoegankelijk. Voor échte kinderfoto's (LoRA) is dat onder art. 25/32 AVG lastig te verdedigen.

Fix minimaal de lora-training/-prefix privé maken met kortlevende presigned URL's; op termijn illustraties/audio achter een geauthenticeerde proxy of presigned URL's.

Hoog

"Foto's binnen 7 dagen gewist" heeft geen afdwingend mechanisme

src/app/api/children/[childId]/lora/route.ts:63-89

De foto-opruiming na training draait alléén wanneer de ingelogde ouder de statusroute toevallig pollt op het moment dat de training net klaar is. Er is geen cron voor. Sluit de ouder de browser tijdens de training, dan blijft de status "training" hangen en blijven foto's + zip onbeperkt staan — feitelijke bewaartermijn ∞ tegenover de beloofde 7 dagen.

Fix dagelijkse cron die trainingen afrondt en na afloop (of na X dagen) deleteTrainingAssets + zip-delete draait.

Hoog

Getraind LoRA-model blijft na verwijdering bij fal.ai staan

src/lib/account/deletion.ts:32-35 · lora-training.ts:145-149

De code erkent dat fal.ai geen delete-API biedt; er verdwijnt dus niets bij die verwerker. Het model — een statistische afgeleide van het gezicht van het kind — blijft na verwijdering bij een Amerikaanse partij, terwijl je privacyverklaring "binnen 7 dagen van beide locaties" belooft (art. 17 + 28(3)(g)).

Fix DPA met wis-clausule regelen of een support-flow navragen; tot die tijd de privacytekst eerlijk maken over wat wel/niet actief verwijderd kan worden.

Hoog

ElevenLabs, Mollie en Sentry ontbreken in de verwerkerslijst

✓ geverifieerd
src/app/privacy/page.tsx:123-148

De volledige verhaaltekst inclusief de kindnaam ("Een verhaal voor {naam}") gaat naar ElevenLabs voor de voorlees-audio; betaal- en adresgegevens naar Mollie; error-metadata naar Sentry. Geen van drie staat in de verwerkerslijst (art. 13(1)(e) AVG). Kleine tekstuele ingreep, grote compliance-winst.

Fix verwerkerslijst aanvullen met deze drie + het doorgiftemechanisme per partij.

Hoog

fal.ai safety-checker staat uit op het LoRA-pad

✓ geverifieerd
src/lib/ai/illustration-generator.ts:59-64

enable_safety_checker: false op het pad dat met het gezicht van een echt kind genereert (en safety_tolerance: "6" — meest permissief — op het pro-pad). De bestaande NSFW-flag-check werkt alleen als de checker aanstaat. Primair een kindveiligheids-/art. 25-risico: een ontspoorde generatie met de gelijkenis van het kind belandt public-read in de bucket.

Fix safety-checker aanzetten op het LoRA-pad en NSFW als harde fail; output-moderatie (Claude Vision) op LoRA-beelden overwegen.

03

Snelheid & schaalbaarheid

De indexdekking is verder volwassen, de rate-limiter is serverless-proof en het admin-dashboard bundelt z'n queries netjes met caching. De grootste risico's zijn een synchrone generatie-request en een paar infra-instellingen die je alleen in het Vercel-dashboard kunt zien.

Hoog

Verhaalgeneratie is één synchrone request tot 120s — credit kwijt bij timeout

✓ geverifieerd
src/app/api/stories/route.ts:29

De hele pipeline (Claude → 7× FLUX + retry → 7 uploads → DB-write) draait binnen één POST die de browser-fetch openhoudt. Wordt de functie op de maxDuration gekild of hapert het netwerk, dan draait de catch níet — de gereserveerde credit wordt niet teruggeboekt en er is geen verhaal. Het GenerationJob-model bestaat al in het schema maar wordt nergens weggeschreven.

Fix naar "start job → 202 + jobId → client pollt", precies het patroon dat LoRA-training al gebruikt. Minimaal: een story-rij met status "generating" vóór de AI-calls, zodat een timeout achteraf detecteerbaar en terug te boeken is.

Middel

ChildProfile.userId heeft geen index — zit in het heetste pad

✓ geverifieerd
prisma/schema.prisma:417-458

Postgres indexeert FK's niet automatisch. Dit veld wordt gebruikt bij élke ownership-check (story openen, audio, pdf, share) en in de dashboard-/funnel-stats. Onmerkbaar nu, lineair pijnlijker bij groei.

Fix @@index([userId]) — één regel migratie, structurele winst.

Middel

Health-check pingt elke minuut de database — Neon slaapt nooit

src/app/api/health/route.ts

De per-minuut SELECT 1 houdt de Neon free tier permanent wakker: ~730 compute-uur/maand tegen een gratis quotum van ~190. Een stille quotum-brander.

Fix monitor-frequentie omlaag, of pingen zonder DB-hit, of het quotum bewust bewaken.

04

Betrouwbaarheid — extra dimensie

Dit heb ik toegevoegd omdat er echte betalingen doorheen gaan en er geen testsuite is. Naast de twee kritieke geldstroom-bugs bovenaan zitten hier vooral race-condities en randgevallen.

Hoog

Verlengings-webhook kan in de "eerste betaling"-branch vallen

src/lib/payments/orders.ts:143-155

De recurring-afhandeling geldt alleen bij !order && isRecurring. Bestaat de renewal-order al (door een eerdere delivery of een crash halverwege), dan valt de latere paid-webhook in de generieke branch, ziet het abonnement al bestaan en returnt vroeg — zonder credits en zonder endsAt te verlengen. De klant betaalt, krijgt niets, en wordt 5 dagen later door de health-cron onterecht op "past_due" gezet met een "incasso mislukt"-mail.

Fix dispatchen op isRecurring ongeacht of de order al bestaat.

Hoog

30-dagen bedenktijd blokkeert alleen pagina's, niet de API's

src/app/(app)/layout.tsx · lib/user-gate.ts

Het verwijder-slot is een layout-redirect. Server-actions en API-routes passeren die layout niet, dus een openstaande tab (of directe POST) kan tijdens de bedenktijd gewoon credits kopen, abonneren en verhalen genereren. Erger: nieuw abonneren tijdens bedenktijd start een verse Mollie-incasso die de deletion-cron nooit meer opzegt — hardDeleteUser cancelt geen abonnement.

Fix deletionRequestedAt meenemen in de user-gate en de checkout-actions; in hardDeleteUser een actieve Mollie-subscription als vangnet cancellen.

05

Wat al goed zit

Belangrijk voor het perspectief: er is veel degelijk gebouwd. Dit is geen brandje maar een volwassen app met een paar scherpe randjes. Een greep uit wat ik expliciet geverifieerd heb.

✓ Autorisatie consequentElke route scoopt eigendom via childProfile: { userId } en geeft 404 bij mismatch. Geen IDOR's gevonden — ook niet op factuur, share of order.
✓ Credit-afschrijving atomairConditionele updateMany met decrement — twee verhalen met 1 credit: de tweede krijgt netjes 402. Geen double-spend.
✓ Webhook vertrouwt client nietLeest alleen het payment-id, haalt de echte status server-to-server bij Mollie op, eist tr_-prefix.
✓ Rate-limiter serverless-proofPostgres fixed-window met atomaire UPSERT + rijlock — geen in-memory valkuil. Vóór elke betaalde AI-call.
✓ Fotomoderatie fail-closedClaude Vision vóór opslag; API-fout → 503 en niets bewaard; bij twijfel afgekeurd; foto's nooit gelogd.
✓ Sterke tokensReset/magic-link 256-bit, alleen SHA-256-hash opgeslagen, single-use met expiry. Share-token 128-bit met 404-cloaking.
✓ Accountverwijdering doordachtVaste volgorde, best-effort per stap, wist ook contact/nieuwsbrief/EmailLog; Orders blijven fiscaal via SetNull.
✓ SSRF-guard op storageScheme-check, IP-blok, private-host-blok en host-allowlist op alle fetches van variabele URL's.
✓ Karaoke-sync defensiefEén gedeelde word-splitter server+client; bij élke mismatch → geen markering i.p.v. een verschoven markering.
✓ Dunning atomairmarkSubscriptionPastDue via updateMany where status:"active"; mails alleen bij echte transitie, met 7d dedupe.
✓ Cookie-verhaal kloptAlleen functionele cookies; Vercel Analytics is echt cookieless; CSP bevestigt geen andere third-party scripts.
✓ Bedragen kloppenAlles in integer-centen, BTW gesnapshot op de order, refund exact op amountCents.
